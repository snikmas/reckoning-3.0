## Working protocol for every implementation ticket

Use this procedure for #143 and #157 through #162:

1. Read `AGENTS.md`, the complete source issue, the complete child issue, and
   all current comments.
2. Run `git status --short --branch`.
3. Fetch the live issue dependencies and verify that every blocker is closed.
4. Compare `HEAD`, `origin/main`, and live `main` before changing code.
5. Inspect the current implementation and tests. Do not trust the snapshot in
   this handoff when current code differs.
6. Add or tighten an acceptance test that fails for the missing behavior.
7. Make the smallest complete end-to-end change that passes the test.
8. Exercise the behavior through supported setup and ordinary interfaces.
9. Run the focused tests for the ticket.
10. Run the full non-live gates.
11. Review the diff for private data, source paths, credentials, misleading
    acceptance claims, and unrelated changes.
12. Commit and push only the ticket's work.
13. Add a GitHub evidence comment with the revision and fresh results.
14. Close the ticket only when every acceptance criterion passes. Leave it
    open with `partial`, failed, blocked, and unrun criteria listed separately
    when any criterion remains.

Do not close #144 only because #157 through #160 are closed. Run the parent
acceptance once on the integrated revision. Apply the same rule to #148 after
#161 through #163.
